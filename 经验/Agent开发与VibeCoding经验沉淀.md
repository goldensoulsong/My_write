# Agent 开发与 Vibe Coding 经验沉淀

记录一下开发和重构 Agent 过程中的一些个人经验和踩坑总结。主要分为安全性、约束机制以及和 AI 结对编程（Vibe Coding）的实际体会。

## 一、 安全性 (Security) 与 强约束体系
让 Agent 跑起来很容易，但失控的代价是毁灭性的。安全性本质上来源于对 Agent 权力的**强力约束**：
1. **防误伤与防越权**：如果不加约束，Agent 极易出现覆盖同名文件、读写系统关键目录等危险操作。必须在底层使用 `os.path.commonpath` 等绝对路径校验机制，将其物理活动范围强制锁死在 `workspace/` 沙盒内，绝不能让它拥有宿主机全局的操作权限。
2. **重成本操作的“物理级拦截墙”**：大模型偶尔会产生幻觉或直接“莽干”。对于如全量精洗 (`llm_batch_clean_text`) 这类极耗 Token 与时间的动作，不能只让 Agent 简单询问“同意吗”。必须设立**特定口令墙**（例如强制核对“我确定使用全参数量精洗”），哪怕它理解了你的含糊同意，也绝不能放行。

## 二、 约束与解耦 (Constraints & Decoupling)
约束的终极解法是：**架构解耦，尽可能把权限拆碎**。
1. **工具层解耦**：永远不要塞给 Agent 一个“大一统”的万能工具箱。将系统划分为 `network`（网络）、`sandbox`（安全沙盒）、`system`（系统），让它在需要时挂载特定维度的能力。
2. **表现侧解耦**：在 UI 层面约束大模型的表现欲。把繁杂的内部推演 (`Thought`) 和 试错日志 (`Action`) 强行剥离到高阶溯源后台（Trace Log），在主交互界面只保留最干净的状态提示和最终成果。
3. **流程化处理与对抗“架构漂移”**：
   - AI 的核心优势在于“自由度”，它拥有远超人类的 I/O 处理能力；但这恰恰也是它最致命的劣势——过高的自由度极易导致**架构漂移 (Architecture Drift)**。
   - 为了对抗这种漂移，系统设计必须建立强流程化的**握手、校验、核实方案**机制。
   - 必须让 ReAct Agent 中的 **"Re" (Reasoning)** 真正体现出严谨的前置思考与推演验证，绝不能让它变成无脑试错的“俺寻思”逻辑 (Ork Logic)。

## 三、 Vibe Coding 协作心法：把 Agent 当作“实习生”
在用自然语言进行系统开发与调用 SOP（标准作业程序）时，人机协作的本质是**带团队**：
1. **输入 Spec 化**：千万不要像和 Siri 聊天一样下达模糊指令。要把需求“Spec 化（产品文档化）”，清晰罗列背景、约束、偏好和不可触碰的红线。
2. **SOP 必须“互动化”与“流程化”**：不要指望大模型能一口气通关复杂任务。SOP 的精髓在于拆解步骤，并在关键节点强制 Agent 停下来“请示”。
3. **“导师与实习生”的带教模式**：
   - **抛出需求**：你给出 Spec。
   - **要求方案**：让这位“实习生 (Agent)”先在脑子里想一遍，并在动手前交出一份具体的 Implementation Plan（执行预案）或语境剖析报告。
   - **确认后放行**：你作为“导师 (Mentor)”，Review 它的方案，指出它的正则会不会误伤剧情、逻辑有没有漏洞，确认无误后再下发执行口令。
   - **这种渐进式的团队成员互动模型，才是 Vibe Coding 确保项目不长歪、稳步推进的唯一真理。**
