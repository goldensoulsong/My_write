### [HTML 的不合理有效性](2026-05-20-HTML的不合理有效性.md)

**原作者**:Thariq Shihipar(Anthropic 技术员工,Claude Code 团队)
**发布**:2026-05-20,Anthropic Blog
**关联文章**:[该等的是 AI](../文章/2026-05-25-该等的是AI.md)

主张把 markdown 全面替换为 HTML 作为人和 AI 协作的输出格式。理由是 HTML 能塞表格、SVG 图、可交互滑块、可分享链接,信息密度更高、视觉更顺、传播更易。文中提供了 spec 与规划、代码审查、设计原型、报告、自定义编辑界面五类用例的具体 prompt。

文章末尾点出真正动机:**HTML 让作者感觉自己还在 Claude 的循环里**——他承认在那之前已经"读 plan 越来越不仔细"。

### [HTML 的不合理无效性](2026-05-10-HTML的不合理无效性.md)

**原作者**:Kurtis Redux
**发布**:2026-05-10,Medium
**关联文章**:[该等的是 AI](../文章/2026-05-25-该等的是AI.md)

对 Thariq 的逐条反驳,从信息密度、视觉清晰度、分享、双向交互、生成成本、审查与版本控制六个维度否定 HTML 替代 markdown。核心立场是 markdown 把内容和表现分离,逼人继续读源、继续亲自处理信息——HTML 把人变成纯读者。

最锋利的一句:**如果你停止读源,你就在外包思考**。这句话比反驳本身大得多——它描述了一个比 markdown vs HTML 之争大得多的现象。

### [约束衰减：LLM智能体在后端代码生成中的脆弱性](2026-05-01-Constraint_Decay_约束衰减.md)

**原作者**: Francesco Dente, Dario Satriani, Paolo Papotti
**发布**: 2026-05, arXiv:2605.06445
**关联文章**: [AI_Agent编程的约束与优化理论探究_系统性论述版本](../文章/AI_Agent编程的约束与优化理论探究_系统性论述版本.md)

介绍了一项系统性研究，揭示了“约束衰减”现象：当 LLM 智能体面临复杂的结构性约束（如架构模式、ORM 约定）时，它们会为了当前的“功能成功”而放弃“架构规则”，收敛到一个在功能上合理但在架构上是灾难的局部最优。主张开发者应转向“上下文工程”并设置严格验证。

### [安全工程经典文献笔记](安全工程经典文献笔记.md)

整理三个 AI 工具设计里值得借鉴、但至少有 30 年积累的经典文献,以及一组当下 AI 行业的标准术语。

- **Reason 瑞士奶酪模型**(*Human Error*, 1990):事故发生在多层防御的洞同时对齐的瞬间。关键不是层数,是**异质性**——同种冗余的洞位置相关,接不住事故。
- **Bainbridge 自动化反讽**(*Ironies of Automation*, 1983):自动化把容易的事做了,留给人的全是难的、罕见的、关键的——而人在这些事上表现最差。控制系统越先进,操作员需要的训练越多,而不是越少。
- **Leveson STAMP / STPA**(*Engineering a Safer World*, 2011):事故大多不是组件失败,是控制结构本身设计错了。STPA 用四个洞分析控制行为:该来的没来、来了不该来、时机错了、持续时间错了。
- **HITL vs HOTL**:human-in-the-loop(每个决策门停下等人按)vs human-on-the-loop(人在旁监督)。当下行业大幅滑向 HOTL——而 HOTL 正是 Bainbridge 警告过的最糟人因配置。
