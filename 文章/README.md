## AI 工具与人机协作

### [该等的是 AI](2026/05/2026-05-25-该等的是AI.md)

读两篇标题对仗的 HTML 之争文章——Anthropic Claude Code 团队 Thariq Shihipar 的《HTML 的不合理有效性》和 Kurtis Redux 的反驳《HTML 的不合理无效性》——之后的元视角思考。

发现两人争的是"该用什么格式让人继续跟得上 AI",但他们共享了一个从未被质疑的前提:**人必须跟得上 AI**。我从安全工程视角反过来论证:这个前提本身就是病灶。

文章建立了四根论证立柱:

- **带宽**——人跟不上 AI 是物理事实,不是格式问题
- **马鞍论**——harness 这个词本意是马鞍,缰绳的强度上限是人手能拉得住的力,不是马能产生的力。现在大部分 AI 工具的设计方向反了
- **奶酪模型 + STAMP**——Reason 的瑞士奶酪模型与 Leveson 的系统理论事故模型,用来诊断坏 harness 设计中"同质冗余 + 把人这片不可替代的奶酪悄悄抽走"的反向使用
- **缸中之脑**——AI 没有需求源,把人挪出 loop 不是把决策权交给 AI,是让系统失去需求的来源,变成一个无主之物

最后翻面讲一面常被忽略的东西:**人也得配得上决策位**。Bainbridge 1983 年的自动化反讽 2 早就说过——控制系统越先进,操作员需要的训练越多,而不是越少。决断质量退化,留位置也没用。

收尾命题:**真正的 in-the-loop 不是一种感觉,是一种控制结构上的位置。**

引用文献:Reason《Human Error》(1990)、Bainbridge《Ironies of Automation》(1983)、Leveson《Engineering a Safer World》(2011)。
